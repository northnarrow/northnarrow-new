| NorthNarrow admin CLI
|
| Usage: nn-admin <COMMAND>
|
| Commands:
|   init                     Generate a fresh Ed25519 keypair, install the public half into the agent's admin.pub, and write the private half to disk for the admin to safeguard. NB: V1 has no air-gapped split flow — keep the private key on a hardware token or removable medium and use `nn-admin unlock --key` only on machines you trust
|   unlock                   Release COMBAT: sign an `unlock` payload over a server-issued challenge (with this install's agent_id and the time) and submit it. Succeeds only when the agent tore the isolation down and read the tables back clear; otherwise exit 9 with what is still in place (the posture stays COMBAT)
|   status                   Print current posture + network isolation state. Add --json to get a machine-readable response for scripting. Without --key the agent answers the posture, the isolation, the last admin action and the COMBAT stage and lock (external audit ASK-009); --key signs the request and adds the telemetry: ring drops and rejected records, the response mode (detect-only), the COMBAT evidence gaps
|   capabilities             Lab PR 218: this boot's signed capability manifest — kernel, BTF, active LSMs, deny hooks and their self-test, each sensor's attach point, host hardening, degradations, the trust level — with the row of the audit chain that signs it. A key with `audit-read` or `telemetry-read` (the signed telemetry read). Exit 1 when the agent has not signed one yet
|   host-check               Host hardening checks (Tappa 10.8): kernel lockdown, module signature enforcement, Secure Boot, unprivileged BPF, kexec, IMA, BPF LSM, single bpffs mount — the settings that keep root from rewriting the kernel at runtime, which is the only way around the agent's anti-tamper. Reads /sys and /proc only; no socket needed. Exit 0 with no warnings, 2 with warnings (`--json` for scripting)
|   detections               Tappa 9.0.b — read the last N persisted detections (newest-first) over the admin socket. Requires a key carrying the low-privilege `telemetry-read` role — read-only telemetry, no COMBAT/control authority. The records stream as JSONL on stdout (so `| jq` works); a summary goes to stderr
|   detection-set-status     Tappa 9.0.c — change a persisted detection's triage status over the admin socket. Requires a key carrying the `triage` role (which also subsumes `telemetry-read`, so a triage key can both read detections and re-status them). Event-sourced: the agent appends a signed status-change event to a separate chain and never mutates the detection log; the new status surfaces on the next `nn-admin detections` read
|   verify-keys              Parse the installed admin.pub, count valid keys, print fingerprints. Local-only — does not touch the agent socket
|   shutdown                 Tappa 8 A9 — signed agent shutdown (design §10)
|   force-posture            Tappa 8 A10 — production signed force-posture (design §4 + §12.2)
|   rotate-keys              Tappa 8 A13 — atomically add or revoke an admin key in `/etc/northnarrow/admin.pub` (design §7.2 + §7.3). Both `add` and `revoke` need a 2-of-N quorum signed by two distinct installed admin keys, at least one of them carrying the `rotate-keys` role; the other may be any installed key, whatever its roles (design §3.3) — custody every installed key as a control credential. `add` grants only roles one of the two signers holds. On success the agent rewrites the file via tmpfile + `rename(2)` and reloads its in-memory key set so the next challenge already sees the change
|   audit                    Tappa 8 A12 — read or verify the tamper-evident audit log (design §9). Two subcommands: `read` streams entries from the on-disk JSONL log, `verify` runs the SHA-256 hash chain + per-entry Ed25519 signature recomputation through `northnarrow_agent::audit::verify_chain`
|   chain                    External audit NN-AUD-112 (lab PR 160) — verify every signed chain in full, offline: the audit log and the canary chains (hashes, signatures, links, row numbers), the rotating logs with their archives, manifest and checkpoints, then the files against the signed head anchor. Exits 8 when a chain is broken or shorter than its anchored head, 0 when everything verifies. Reads the files directly (root: they are 0600 or under 0700 directories)
|   fim                      Tappa 9 C6 — FIM operator surface. `fim baseline` queues a re-compute of the watched-paths SHA-256 baseline (signed payload, single-sig `fim-manage` role per §13 Q6). `fim report [--since <unix-ts>]` reads the chained drift log (signed payload, single-sig `fim-read` role)
|   canary                   Tappa 9.5 K6 — deception canary operator surface. `canary deploy` installs a new canary (File / Process / Network / Credential variants), `canary list` streams the chained registry log, `canary burn` permanently retires a canary, `canary refresh` re-renders the on-disk artefact. Authorisation: `canary-read` for `list`; `canary-manage` for `deploy` / `burn` / `refresh` (§12 Q7 SPLIT lock-in)
|   net                      Tappa 10 N7 — network observability operator surface. `net flows` reads the chained netflow log, `net listeners` snapshots active listeners, `net resolve <ip>` looks up DNS attribution, `net fingerprint --flow-id <hex>` dumps JA3/JA4. All four are `Role::NetRead` (1-of-N quorum per §13 Q6)
|   trusted-installer-grant  FIM-009 self-upgrade (§15.1) — arm the trusted-installer override for an in-place agent upgrade. Submits a 1-of-N (M=1) quorum-signed grant; the admin.pub line for `--key` MUST carry the `trusted-installer` role. While the window is open the agent's FS pin is suspended (so install.sh can replace the protected binary) AND a write to the agent's OWN systemd units is downgraded from kill to an audit Log. The window is bounded by --window-secs (clamped to the agent's 600 s ceiling) and by the next agent restart. Operator flow: grant → install.sh → `systemctl restart` → signed `fim baseline`
|   response                 External audit CMB-016 — undo what the response layer did: `response status` lists the processes the agent holds in its containment scopes, the quarantine vault and the COMBAT stage (`audit-read`); `response release` returns a contained process to the cgroup it came from and `response restore` writes a quarantined file back out of the vault (`response-manage`). The agent does the work and records it in the signed audit log
|   remediate                Lab PR 222 — undo what ransomware rewrote, from the copy-on-first- write journal (`remediate ransomware`, `response-manage`). The agent restores and signs one `cow_restore` row per file
|   config                   Tappa 10.8 — operator configuration the agent loads only when an admin key signed it (`config overlay set|sign|status`)
|   policy                   Lab PR 236 — the signed per-rule response policy (`rule-policy.local`): which rules enforce, alert, audit or are off, their exemptions. `show` the policy in force, `set` a new one (signed, applied at once), `test` a candidate on sample events
|   help                     Print this message or the help of the given subcommand(s)
|
| Options:
|   -h, --help     Print help
|   -V, --version  Print version

| Stream the audit log to stdout, optionally filtered by timestamp. Default output is a compact human-readable summary; `--json` emits one canonical JSON object per line (matches the on-disk JSONL exactly).
|
| Who acted: the key fingerprint (`key_fp`, `cosigner_fps`) is the operator's identity. `client_pid`/`client_uid` come from the kernel (SO_PEERCRED); `client_comm` is the name the connecting process gave itself, which any process chooses; `client_exe` (rows from lab PR 179 on) is the program the kernel says it ran.
